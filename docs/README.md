# 文档索引

## 说明

- 这里同时保存本工作区的项目说明，以及给 Codex / Claude / 其他工程助手复用的通用提示词与模板。
- 这些文件分成三类：
  - 项目事实：当前工作区的产品定位、架构方向和落地边界
  - 模板契约：用于生成项目级 `AGENTS.md` 或项目冷启动流程
  - 专项提示词：在特定任务场景下按需引用，不应默认全部叠加
- 使用原则：
  - 先看根目录 `AGENTS.md` 和 `README.md`
  - 再看与任务直接相关的项目事实或子项目文档
  - 最后按需选择模板或专项提示词
  - 不要把整个目录机械复制进任何子项目

## 推荐用法

### 1. 做冷启动或重建项目契约

顺序：
1. 先看 [冷启动.md](./冷启动.md)
2. 再结合根目录 `AGENTS.md`、`README.md` 和 [项目说明.md](./项目说明.md)
3. 按实际情况补充或裁剪 `README`、`docs/`、脚本说明和测试说明
4. 如果需要固定 skill 触发规则，再参考 [skills.md](./skills.md)

### 2. 做普通开发任务

- 默认只参考根或子项目自己的 `AGENTS.md` / `CLAUDE.md`、`README.md` 和相关源码。
- 只有在项目约束不足或任务明显命中专项场景时，才回到本目录取用单个文档。

### 3. 做专项任务

- 安全/权限/信任边界：看 [代码审计.md](./代码审计.md)
- 需要更强过程约束：按需摘取 [强前置条件约束.md](./强前置条件约束.md) 中的条目
- 需要补目录和模块边界：看 [代码组织.md](./代码组织.md) 和 [通用项目架构模板.md](./通用项目架构模板.md)
- 需要固定 skill 触发与导引：看 [skills.md](./skills.md)

## 维护约定

- 新增项目事实文档时，应在本 README 中注明它适用的项目范围。
- 新增模板时，优先写成“可裁剪模板”，而不是对所有项目都生效的强制规则。
- 新增专项提示词时，应在本 README 中注明触发场景与不适用场景。
- 如果某份提示词长期只适用于单一项目，应迁回那个项目自己的 `AGENTS.md` 或 `docs/`，不要继续放在通用模板目录里。
