# 后续阶段总览

本文串联 MVP 之后需要本次补齐的阶段三、阶段四，避免后续开发只看单份文档时丢失顺序。

## 阶段三：可自定义工作站

详见 [设置页面.md](./设置页面.md)。

目标：

- 用户可以不改代码配置工作站。
- 用户可以启用/禁用 widgets。
- 用户可以创建和绑定 timer policy。
- 用户可以配置 ActivityWatch、Tokei、GitHub、音乐 mood 和主题。
- 用户可以导出数据、导入旧 Task-Manager 数据。

优先级：

1. settings 数据模型和 API。
2. `/settings/workstation` 页面。
3. Widgets 与计时策略配置。
4. ActivityWatch / Tokei / GitHub / Music 配置。
5. 数据导入导出与隐私说明。

完成标志：

```text
用户能通过 UI 配置工作站，不再依赖改代码或手写 YAML。
```

## 阶段四：可分发产品

详见 [封装与发布.md](./封装与发布.md)。

目标：

- Docker 版可部署。
- Windows 桌面版可安装。
- SQLite 数据持久化稳定。
- core 能随桌面 shell 自动启动。
- 托盘、快捷键、桌面歌词、全屏 break 等桌面能力具备落地路径。

优先级：

1. Docker Compose。
2. Homepage 与 core Dockerfile。
3. Electron desktop shell。
4. Windows 用户数据目录。
5. 安装、更新、卸载策略。

完成标志：

```text
用户可以通过 Docker 或 Windows 安装包运行认知工作站，并且重启后数据不丢失。
```

## 阶段依赖关系

```text
阶段二 MVP
  ↓
阶段三设置页
  ↓
阶段四封装发布
```

例外：

- 阶段四的用户数据目录可以提前影响阶段三的“数据与隐私”设置。
- 阶段三的设置模型必须先于阶段四发布，否则 Docker/Windows 用户只能改环境变量。

## 不做事项

后续阶段仍不包含：

- 多用户系统。
- 云同步。
- 移动端。
- AI 自动规划。
- 绕过音乐平台限制。
- 复制完整 Super Productivity UI。
- 重写 ActivityWatch watcher。
