# 阶段五优化落地

> 状态：本次只优化已有闭环，不代做仍在逐步实现的完整设置页、诊断页、导出、自动清理、Docker/Windows 产品化。

## 本次优化范围

- 任务：保留现有任务创建、完成、从任务开始专注能力。
- 弹性计时：保留开始、暂停、继续、结束、拆分、调整能力，并增强手动调整留痕。
- 增强模块：ActivityWatch、Tokei、GitHub、音乐仍然是可降级模块，失败不阻断任务和计时。
- 每日复盘：继续聚合任务、计时、活动统计、音乐和问题提示，但把增强模块失败明确列为“问题提示”。
- `/workstation` 页面：优化面向用户的文案、空状态、错误状态和降级提示，不暴露内部 widget key。

## 数据与保留原则

- 长期保留：任务、项目、计时策略、专注记录、时间片段、每日复盘、用户主动调整记录。
- 短期或可丢弃：ActivityWatch 原始标题、API 原始响应、音乐搜索结果、调试日志、临时缓存。
- 不入库：明文音乐平台 Cookie、GitHub access token、系统凭据、完整音频文件、大型二进制封面、高频键鼠明细。
- 字段化：经常用于查询、排序、筛选、关联和统计的字段，例如 `tasks.status`、`tasks.planned_date`、`focus_sessions.started_at`。
- JSON 化：标签、上下文、活动证据、音乐上下文、外部 payload 等不作为主查询条件的扩展信息。

## 已落地的代码优化

- SQLite 初始化补充任务、计时、时间片段、活动快照和复盘日期索引。
- `/api/activity/summary` 只返回当天聚合结果，不再把 Tokei/GitHub/ActivityWatch 原始 payload 暴露给首页。
- Tokei 统计增加 5 分钟内存缓存，避免首页刷新反复运行 collector。
- 手动拆分、调整、结束计时都会记录 `at`、`reason`、`source`、`before`、`after` 和 `changes`。
- ActivityWatch、Tokei、GitHub 失败时返回用户可理解的中文提示，并说明核心功能不受影响。
- `/workstation` 页面统一为“任务 / 弹性计时 / 电脑活动 / 音乐 / 每日复盘”等用户概念。

## 后续清单

- 完整设置页：设置分组、高级项折叠、数据与隐私设置。
- 诊断页：核心服务状态、SQLite 路径、数据库大小、模块连接状态、最近错误。
- 导出：完整导出与隐私导出。
- 自动清理：缓存、日志、ActivityWatch 原始明细、音乐搜索历史。
- daily summary 持久化：把当天聚合结果写入 summary 表，而不是仅运行时计算。
- Docker/Windows 产品化：保持 `docs/封装与发布.md` 的规划，不在本次代做。

## 验收

- 未启动 ActivityWatch / 缺失 Tokei / GitHub 网络失败时，任务和计时仍可用。
- 首页不展示内部字段名、widget key 或原始 JSON。
- 手动调整记录能说明调整前、调整后、原因和来源。
- 数据模型文档能解释字段化与 JSON 化边界。
