# 阶段四：封装与发布

> 状态：Docker Compose 与可安装的 Electron desktop shell 已落地。桌面版已内置 Homepage standalone、core、SQLite、图标、托盘、快捷键和数据目录；生产级代码签名、自动更新与 CI 发布仍需继续。

## 1. 目标

第四阶段目标是把开发态工作站变成可部署、可安装、可分发的产品。

发布形态：

```text
1. Docker / self-hosted
2. Windows desktop
```

边界：

- Docker 版主打自托管和本地服务部署。
- Windows 版主打普通用户直接安装和桌面能力。
- 阶段四不新增核心业务功能，只补运行、封装、更新、数据目录和故障恢复。

## 2. Docker 版

### 2.1 目标

Docker 版支持：

- Homepage 主界面。
- `workbench-core`。
- SQLite 数据持久化。
- 开发统计（Token / GitHub）。
- ActivityWatch 外部连接。
- 可选音乐服务连接。

Docker 版不强制支持：

- 桌面歌词。
- 系统托盘。
- 全局快捷键。
- 全屏休息。
- Windows 原生通知。

### 2.2 镜像结构

建议拆两个镜像：

```text
ghcr.io/your-org/research-workstation-homepage
ghcr.io/your-org/research-workstation-core
```

原因：

- Homepage 和 core 生命周期不同。
- core 需要 SQLite 数据目录。
- Homepage 可以无状态发布。

后续可以再提供 all-in-one 镜像，但不作为第一优先级。

### 2.3 Dockerfile 规划

Homepage：

```text
apps/homepage/Dockerfile
```

职责：

- 安装 workspace 依赖。
- 构建 `packages/theme` 与 Homepage。
- 暴露 `3000`。
- 运行 `pnpm --filter homepage start`。

Workbench Core：

```text
services/workbench-core/Dockerfile
```

职责：

- 安装 workspace 依赖。
- 构建 `packages/contracts` 与 `services/workbench-core`。
- 暴露 `3900`。
- 挂载 `/app/data`。
- 运行 `node dist/index.js`。

### 2.4 Docker Compose

目标文件：

```text
deploy/docker-compose.yml
```

当前已实现该文件，可从仓库根目录运行：

```bash
docker compose -f deploy/docker-compose.yml up --build
```

建议内容：

```yaml
services:
  research-workstation-homepage:
    image: ghcr.io/your-org/research-workstation-homepage:latest
    container_name: research-workstation-homepage
    ports:
      - "3000:3000"
    environment:
      WORKBENCH_CORE_URL: http://workbench-core:3900
    depends_on:
      - workbench-core

  workbench-core:
    image: ghcr.io/your-org/research-workstation-core:latest
    container_name: workbench-core
    ports:
      - "3900:3900"
    volumes:
      - ./data:/app/data
      - ./config:/app/config
    environment:
      DATABASE_URL: file:/app/data/workbench.sqlite
      ACTIVITYWATCH_URL: http://host.docker.internal:5600
      GITHUB_USERNAME: ""
      TOKEI_REPO: /app/tokei
```

### 2.5 数据目录

Docker 数据目录：

```text
data/
  workbench.sqlite
  exports/
  cache/
    github/
    tokei/
    activitywatch/
    music/

config/
  settings.yaml
  timer-policies.yaml
  projects.yaml
  widgets.yaml
```

SQLite 属于必须持久化数据。缓存可以清理，不能作为唯一事实来源。

### 2.6 环境变量

| 变量 | 默认值 | Docker 说明 |
|:---|:---|:---|
| `DATABASE_URL` | `file:/app/data/workbench.sqlite` | 必须持久化 |
| `WORKBENCH_CORE_URL` | `http://workbench-core:3900` | Homepage 容器内访问 core |
| `ACTIVITYWATCH_URL` | `http://host.docker.internal:5600` | 访问宿主 ActivityWatch |
| `GITHUB_USERNAME` | 空 | 可选 GitHub 用户名 |
| `TOKEI_REPO` | `/app/tokei` | 需要挂载或禁用 |
| `MUSIC_SERVICE_URL` | 空 | 可选音乐服务 |

### 2.7 Docker 验收

1. `docker compose up` 后 Homepage 可访问。
2. `workbench-core` `/health` 可访问。
3. 重启容器后任务、计时、复盘和设置不丢失。
4. Homepage widgets 能读取 core。
5. ActivityWatch 可通过 `host.docker.internal` 连接。
6. GitHub/token 统计可配置。
7. 无 ActivityWatch / Tokei 时核心任务与计时仍可用。

## 3. Windows 桌面版

### 3.1 目标

Windows 桌面版当前支持：

- 首页工作站。
- 本地 `workbench-core` 自动启动。
- 本地数据库。
- 系统托盘。
- 全局快捷键。
- 音乐播放。
- ActivityWatch 检测。

尚未实现：桌面歌词、全屏休息窗口、Windows 原生通知、开机启动、自动更新和发行证书签名。

### 3.2 应用结构

当前已实现：

- `src/main.ts`

- `src/services/coreProcess.ts`
- `src/services/homepageProcess.ts`
- `src/services/runtimeProcess.ts`
- `scripts/run-builder.mjs`

### 3.3 Desktop Shell 职责

- 启动 Homepage 前端。
- 启动 `workbench-core` 子进程。
- 注入 `DATABASE_URL`、`ACTIVITYWATCH_URL`、`MUSIC_SERVICE_URL`。
- 管理托盘。
- 管理全局快捷键。
- 校验 renderer IPC 来源并把外链交给系统浏览器。
- 管理两个本地服务的健康检查、日志与退出生命周期。

### 3.4 进程模型

```text
Electron main
  ├─ workbench-core child process
  ├─ Homepage standalone child process
  ├─ Homepage renderer window
  └─ system tray
```

原则：

- core 由 shell 管理生命周期。
- renderer 不直接访问文件系统。
- renderer 通过 HTTP API 调 core。
- Electron IPC 只处理桌面能力，不承载业务状态。

### 3.5 Windows 用户数据目录

```text
%APPDATA%/Research Workstation/
  data/workbench.sqlite
  config/homepage/
  config/nextauth-secret
  logs/workbench-core.log
  logs/homepage.log
```

卸载策略：

- 默认不删除用户数据。
- 如果提供“删除用户数据”选项，必须明确提示不可恢复。

### 3.6 快捷键

第一批全局快捷键：

| 功能 | 默认快捷键 |
|:---|:---|
| 开始/暂停计时 | `Ctrl+Alt+Space` |
| 停止计时 | `Ctrl+Alt+S` |
| 播放/暂停音乐 | `Ctrl+Alt+P` |
| 显示/隐藏主窗口 | `Ctrl+Alt+H` |

快捷键必须可关闭，避免和用户已有工具冲突。

### 3.7 打包

使用：

```text
electron-builder
```

当前产物：

```text
apps/desktop-shell/release/ResearchWorkstation-<version>-x64.exe
apps/desktop-shell/release/ResearchWorkstation-<version>-x64.exe.blockmap
apps/desktop-shell/release/win-unpacked/
```

安装包行为：

- 创建桌面快捷方式。
- 创建开始菜单快捷方式。
- 用户级安装。
- 默认不需要管理员权限。
- 不创建开机启动项。

### 3.8 自动更新

第一版可选：

- 使用 `electron-updater`。
- 仅 Windows 桌面版启用。
- 更新前提示用户。
- 更新失败不影响当前版本继续使用。

### 3.9 Windows 验收

1. 用户下载安装包后可以直接安装；未签名版本可能触发 SmartScreen。
2. 安装后桌面快捷方式可启动。
3. `workbench-core` 自动启动。
4. 关闭主窗口后可选择托盘常驻。
5. 全局快捷键可控制计时器和音乐。
6. 音乐控制可用。
7. ActivityWatch 可检测连接状态，断连不阻塞主功能。
8. 数据重启后不丢失。
9. 卸载后不误删用户主动保留的数据。

## 4. 发布流程

建议脚本：

```json
{
  "scripts": {
    "build:docker": "pnpm --filter homepage build && pnpm --filter @cw/workbench-core build",
    "desktop:build": "pnpm --filter @cw/contracts build && pnpm --filter @cw/workbench-core build && pnpm --filter homepage build && pnpm --filter @cw/desktop-shell build",
    "desktop:dev": "pnpm desktop:build && pnpm --filter @cw/desktop-shell dev",
    "desktop:pack": "pnpm desktop:build && pnpm --filter @cw/desktop-shell pack",
    "desktop:dist": "pnpm desktop:build && pnpm --filter @cw/desktop-shell dist"
  }
}
```

当前根 `package.json` 已提供：

```bash
pnpm build:docker
pnpm desktop:dev
pnpm desktop:build
pnpm desktop:pack
pnpm desktop:dist
```

版本发布顺序：

1. 更新版本号。
2. 运行 core 测试。
3. 运行 Homepage build。
4. 构建 Docker 镜像。
5. 构建 Windows 安装包。
6. 生成 release notes。
7. 发布 GitHub Release。

## 6. 风险控制

### 6.1 原生依赖

`better-sqlite3` 可能需要原生构建。

控制：

- 固定 Node LTS 版本。
- 打包前退出开发态 core，避免 Windows 文件锁阻止 Electron ABI 重建。
- `scripts/run-builder.mjs` 在打包后恢复 Node.js ABI 的原生模块。
- CI 覆盖 Windows。
- 失败时记录安装指引。

### 6.2 ActivityWatch 外部依赖

用户可能未安装 ActivityWatch。

控制：

- Docker/Windows 都把 ActivityWatch 视为增强模块。
- 未连接时展示说明，不阻断任务和计时。

### 6.3 音乐平台限制

音乐接口涉及账号、版权和平台规则。

控制：

- 不提供破解或绕过能力。
- 第一版桌面版只支持用户自有账号或本地服务。

### 6.4 数据损坏

SQLite 是核心数据。

控制：

- 自动备份。
- 导出功能。
- migration 前备份。
- 删除数据二次确认。
