# 阶段三：工作站设置页面

> 状态：页面与 API 已实现到可操作 MVP。高级拖拽、完整旧 Task-Manager 写入和更细的校验仍需继续打磨。本文把 `docs/开发指南.md` 阶段三落成可执行规格。

## 1. 目标

第三阶段目标是让用户不改代码、不手写 YAML，也能配置认知工作站。

新增页面：

```text
apps/homepage/src/pages/settings/workstation.jsx
```

当前已实现：

```text
/settings/workstation
GET/PATCH /api/settings/workstation
GET/PATCH /api/settings/widgets/:id
GET/POST/PATCH/DELETE /api/settings/timer-policies
GET /api/settings/export
POST /api/settings/import
POST /api/settings/reset-cache
POST /api/settings/delete-all-data
```

设置目前会实际影响：

- `/workstation` widget 显示/隐藏。
- ActivityWatch 读取地址和启用状态。
- Tokei collector 路径和 Python 路径。
- GitHub 贡献统计用户名。
- 音乐模块启用状态和 remote/mock provider。
- timer policy CRUD 与任务绑定。

核心原则：

- Homepage 负责设置 UI。
- `workbench-core` 负责保存设置、校验设置、导入导出数据。
- 设置默认保存在 SQLite，必要时可导出为 YAML/JSON。
- 设置页只管理工作站相关内容，不改 Homepage 原有通用设置体系。

## 3. 数据模型

新增表建议：

```sql
CREATE TABLE workstation_settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE widget_settings (
  id TEXT PRIMARY KEY,
  enabled INTEGER NOT NULL,
  modes_json TEXT NOT NULL,
  refresh_interval_seconds INTEGER,
  size_json TEXT,
  position_json TEXT,
  options_json TEXT,
  updated_at TEXT NOT NULL
);
```

共享类型建议放入：

```text
packages/contracts/src/index.ts
```

核心类型：

```ts
export interface WidgetSettings {
  id: string;
  enabled: boolean;
  modes: WorkstationMode[];
  refreshIntervalSeconds?: number;
  size?: { w: number; h: number };
  position?: { x: number; y: number };
  options?: Record<string, unknown>;
  updatedAt: string;
}

export interface WorkstationSettings {
  defaultMode: WorkstationMode;
  modes: Record<WorkstationMode, ModeSettings>;
  activitywatch: ActivityWatchSettings;
  activityStats: ActivityStatsSettings;
  music: MusicSettings;
  privacy: PrivacySettings;
  theme: ThemeSettings;
}
```

## 4. API 设计

新增 API：

```text
GET    /api/settings/workstation
PATCH  /api/settings/workstation

GET    /api/settings/widgets
PATCH  /api/settings/widgets/:id
POST   /api/settings/widgets/reorder

GET    /api/settings/timer-policies
POST   /api/settings/timer-policies
PATCH  /api/settings/timer-policies/:id
DELETE /api/settings/timer-policies/:id

GET    /api/settings/export
POST   /api/settings/import
POST   /api/settings/reset-cache
POST   /api/settings/delete-all-data
```

Homepage proxy 对应：

```text
/api/workstation/settings/*
```

API 约束：

- 所有写入接口必须返回保存后的完整对象。
- 删除计时策略前必须检查是否仍有任务或 session 引用。
- 导入旧 Task-Manager 数据必须先预览，再确认写入。
- 删除所有数据必须二次确认，并支持导出备份。

## 5. 分区规格

### 5.1 总览

显示：

- core 是否连接。
- SQLite 数据库路径。
- ActivityWatch 是否连接。
- Tokei/GitHub 是否可用。
- 音乐服务模式：mock / remote。
- 当前默认工作站模式。

操作：

- 打开数据目录。
- 导出所有数据。
- 运行诊断检查。

### 5.2 工作站模式

内置模式：

```text
study
coding
writing
music
review
rest
```

每个模式可配置：

- 默认 widgets。
- 默认主题。
- 默认音乐 mood。
- 默认计时策略。
- 是否启用 ActivityWatch 校准。
- 是否启用 GitHub/token 统计。

默认策略：

- `study`：强调任务、计时、ActivityWatch。
- `coding`：强调 GitHub、token、项目。
- `music`：强调音乐状态和封面/歌词。
- `review`：强调统计、时间线、复盘。
- `rest`：强调低刺激和休息提示。

### 5.3 Widgets

用户可配置：

- 启用/禁用。
- 所属模式。
- 刷新频率。
- 显示大小。
- 显示顺序。
- 数据源选项。

MVP 后续第一批 widgets：

```text
workstation.task-board
workstation.flex-timer
workstation.token-usage
workstation.github-heatmap
workstation.activitywatch-now
workstation.activity-summary
workstation.music-mini
workstation.daily-review
```

刷新频率建议：

| Widget | 默认刷新 |
|:---|:---|
| timer | 1s |
| activitywatch-now | 10s |
| token-usage | 5min |
| github-heatmap | 5min |
| music-mini | 2s |
| daily-review | 手动 |

### 5.4 任务与项目

项目设置项：

- 名称、颜色、图标。
- 默认计时策略。
- 默认音乐 mood。
- GitHub 仓库。
- 本地路径。
- 常用命令。

任务设置项：

- 默认 planned date。
- 默认标签。
- 是否允许无项目任务。
- 是否完成任务时自动关闭计时。

### 5.5 计时器

这是阶段三核心。

内置策略：

```text
elastic-50-10
deep-math
coding-elastic
writing-block
review-light
rest-protected
```

设置项：

- 模式：正向计时 / 固定番茄 / 弹性番茄 / 预算分割 / 截止倒推。
- 默认专注时长。
- 默认休息时长。
- 最短 session。
- 最长 session。
- 是否允许延长、缩短、跳过休息、合并、拆分、手动调整。
- 是否启用 AFK 校准。
- 是否启用强提醒和全屏休息。

安全默认：

- 允许手动调整。
- 所有调整写入 `adjustmentLog`。
- 不做不可关闭的强制锁屏。

### 5.6 音乐

服务设置：

- mock 模式。
- `MUSIC_SERVICE_URL` 远端服务模式。
- 后续 Mineradio service 地址。

mood：

```text
deep-focus
coding
writing
ambient
review
relaxed
weather-radio
```

联动规则：

- mode -> mood。
- project -> mood。
- task tag -> mood。

### 5.7 活动监控

设置项：

- 是否启用 ActivityWatch。
- `ACTIVITYWATCH_URL`。
- 是否读取 window / afk / web watcher。
- AFK 阈值。
- 是否用 ActivityWatch 校准计时器。
- 是否在复盘中展示活动证据。

默认：

```yaml
activitywatch:
  enabled: true
  baseUrl: http://127.0.0.1:5600
  watchers:
    window: true
    afk: true
    web: true
  afkCorrection:
    enabled: true
    thresholdMinutes: 5
```

### 5.8 活动统计

设置项：

- `TOKEI_REPO`。
- `TOKEI_PYTHON`。
- `GITHUB_USERNAME`。
- 刷新频率。
- 是否缓存。
- 是否进入每日复盘。
- 是否关联当前项目。

失败策略：

- Tokei 路径不存在：显示路径检查提示。
- GitHub 网络失败：保留上次缓存。
- Python 不可用：显示解释和修复命令。

### 5.9 主题

内置主题：

```text
default-dark
parchment-light
deep-study
coding
music-cinema
review-paper
rest-soft
```

设置项：

- 全局主题。
- 模式主题。
- widget 透明度。
- 背景模糊。
- 动画强度。
- 字体。
- 圆角。
- 卡片密度。

约束：

- 所有工作站 UI 使用 `packages/theme` token。
- 不允许 widget 写死大面积颜色。
- music mode 可以更强视觉，study/coding 默认低干扰。

### 5.10 数据与隐私

用户可以：

- 查看本地数据库位置。
- 导出全部数据。
- 导入旧 Task-Manager 数据。
- 清理音乐缓存。
- 清理 ActivityWatch 缓存。
- 清理 token/GitHub 缓存。
- 删除全部数据。

隐私说明必须显示：

- 工作站数据默认保存在本机。
- ActivityWatch 数据来自用户本机。
- 音乐平台登录态只保存在本机。
- token/GitHub 统计只用于本地展示和复盘。

## 6. 验收标准

阶段三完成时必须满足：

1. 用户可以不改代码启用/禁用 widgets。
2. 用户可以不改代码创建 timer policy。
3. 用户可以把任务绑定到 timer policy。
4. 用户可以把项目绑定到 music mood。
5. 用户可以配置 ActivityWatch 地址。
6. 用户可以配置 GitHub 用户名。
7. 用户可以配置 Tokei 路径。
8. 用户可以切换主题。
9. 用户可以导出数据。
10. 用户可以导入旧 Task-Manager 数据。
