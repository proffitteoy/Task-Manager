# 架构

## 总体边界

```text
Homepage /workstation
  ↓
/api/workstation/* proxy
  ↓
workbench-core
  ↓
SQLite + adapters
```

- `apps/homepage`：展示、布局、交互与 widget 编排。
- `services/workbench-core`：状态、规则、任务、计时、复盘和外部数据适配。
- `packages/contracts`：共享 TypeScript 类型。
- `packages/theme`：统一工作站主题 token。

## 数据流

1. 用户在 `/workstation` 创建任务。
2. Homepage 通过 `/api/workstation/tasks` 转发到 `workbench-core`。
3. 任务启动计时时创建 `focus_sessions` 和 `focus_segments`。
4. ActivityWatch、Tokei、GitHub、Music 数据由 core adapter 读取或 mock。
5. 每日复盘聚合当天任务、计时、活动、音乐和调整日志，写入 `daily_reviews`。

## 集成策略

- ActivityWatch 只读，不重写 watcher。
- Tokei/GitHub 从旧 `Task-Manager-main` 的本地 API 思路迁入 core。
- Mineradio 源码未在仓库中，音乐模块第一版只做 mock/proxy。
- BreakTimer 与 Super Productivity 保留为机制和模型参考，不直接嵌 UI。
