# 运行与验证

## 安装

```bash
pnpm install
```

如果环境限制网络访问，需要先允许访问 npm registry。

## 启动

```bash
pnpm dev:core
pnpm dev:homepage
```

访问：

- `http://127.0.0.1:3900/health`
- `http://localhost:3000`
- `http://localhost:3000/settings/workstation`

## 验证

```bash
pnpm --filter @cw/workbench-core build
pnpm --filter @cw/workbench-core test
pnpm --filter homepage lint
pnpm --filter homepage test
pnpm --filter homepage build
pnpm --filter @cw/desktop-shell build
```

本次阶段五已有功能优化重点验证：

- SQLite 初始化后存在任务、计时、时间片段、活动快照和复盘日期索引。
- 手动拆分、调整、结束计时后，调整记录包含调整前、调整后、原因、来源和时间。
- `/api/activity/summary` 只返回当天聚合摘要，不返回外部模块原始 payload。
- ActivityWatch、Tokei、GitHub 不可用时，页面显示中文降级提示，任务和计时仍可使用。
- 首页不展示 `workstation.*`、`payload_json` 等内部字段名。

## MVP 手工验收

1. 打开 `/`。
2. 新增任务。
3. 从任务启动专注。
4. 暂停、继续、拆分、结束 session。
5. 查看今日专注、token、GitHub、ActivityWatch、音乐状态。
6. 点击“生成今日复盘”。
7. 打开 `/settings/workstation`，切换默认模式、启用/禁用组件、创建计时策略。
8. 在 `/settings/workstation` 修改 ActivityWatch URL、Tokei 路径、GitHub 用户名和音乐启用状态后，确认对应 API 返回新设置。

## Docker smoke

```bash
docker compose -f deploy/docker-compose.yml up --build
```

验收：

- `http://localhost:3000` 可访问。
- `http://localhost:3900/health` 返回 `ok: true`。
- 重启容器后 `deploy/data/workbench.sqlite` 仍存在。

## Desktop shell smoke

```bash
pnpm --filter @cw/contracts build
pnpm --filter @cw/workbench-core build
pnpm --filter @cw/desktop-shell build
pnpm --filter @cw/desktop-shell dev
```

开发态默认打开 `http://localhost:3000`，因此需要先启动 Homepage，或设置 `HOMEPAGE_URL` 指向可用地址。
8. 未启动 ActivityWatch、缺失 Tokei collector 或 GitHub 网络失败时，页面仍可创建任务和计时。
