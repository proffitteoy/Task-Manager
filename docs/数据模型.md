# 数据模型

数据库默认路径：`services/workbench-core/data/workbench.sqlite`，可通过 `DATABASE_URL=file:<path>` 修改。

## 表

- `projects`：项目名称、颜色、图标。
- `tasks`：任务标题、状态、来源、标签、上下文、预估时长和计划日期。
- `timer_policies`：弹性计时策略，默认 seed `elastic-50-10`。
- `focus_sessions`：一次专注会话，关联任务、项目、策略、活动证据、音乐上下文和调整日志。
- `focus_segments`：会话分段，支持 `focus`、`break`、`afk`、`manual`。
- `activity_snapshots`：活动快照预留表，用于后续缓存 ActivityWatch、Tokei、GitHub、music 数据。
- `daily_reviews`：每日复盘聚合结果。
- `music_state`：本地 mock 音乐状态。
- `workstation_settings`：工作站基础设置。
- `widget_settings`：工作站 widget 的启用、模式、刷新频率和布局设置。

## 查询索引

初始化数据库时会创建第一批必要索引：

- `tasks.status`、`tasks.project_id`、`tasks.planned_date`、`tasks.timer_policy_id`
- `focus_sessions.task_id`、`focus_sessions.project_id`、`focus_sessions.started_at`、`focus_sessions.ended_at`
- `focus_segments.session_id`、`focus_segments.started_at`
- `activity_snapshots(source, date)`
- `daily_reviews.date`

这些索引用于避免首页、今日摘要、复盘和计时明细查询随着历史数据增长而退化为全表扫描。

## 字段化与 JSON 化

- 经常用于查询、排序、筛选、关联和统计的数据必须落字段，例如任务状态、计划日期、计时开始/结束时间。
- 只用于扩展展示或保留上下文的数据可以放 JSON，例如任务标签、任务上下文、活动证据、音乐上下文和外部 payload。
- JSON 字段中不应隐藏关键查询条件；如果 UI 或统计经常按某个值过滤，应升级为结构化字段。

## 调整记录

计时拆分、归属调整、时长调整和手动结束会写入 `focus_sessions.adjustment_log_json`。

每条调整记录至少包含：

- `at`：调整时间。
- `reason`：用户或系统给出的原因。
- `source`：来源，当前主要为 `user`。
- `before`：调整前的关键值。
- `after`：调整后的关键值。
- `changes`：结构化变化摘要。

这样每日复盘可以解释“计划如何被现实修正”，同时保持旧数据兼容。

## 敏感数据

- ActivityWatch、浏览器标题、音乐账号、token/GitHub 统计都按敏感本地数据处理。
- 不把明文音乐平台 Cookie、GitHub access token、系统凭据、完整音频文件、大型封面二进制或高频键鼠事件写入 SQLite。
- `/api/activity/summary` 面向首页只返回当天聚合数据和模块状态，不返回外部模块原始 payload。

## 兼容原则

- 业务 JSON 先保存在 `*_json` 字段；只有明确成为核心查询条件时再迁移为字段或拆表。
- ActivityWatch 是增强数据，不影响任务、计时、复盘基础流程。
- 调整日志必须保留，方便复盘“计划如何被现实修正”。
