## 6. 阶段二：整合成一个项目

### 6.1 阶段目标

第二阶段开始正式整合。目标是以 Homepage 为 base，建立一个可以运行的全流程工作站 MVP。

MVP 不追求完整音乐视觉、不追求完整 ActivityWatch 复盘、不追求完整桌面打包。MVP 只要求核心闭环跑通：

```bash
任务 -> 计时 -> 活动统计 -> 音乐状态 -> 每日复盘
```

### 6.2 工作内容

services:

## 11. 风险与控制

### 11.1 拼接风险

风险：

```bash
多个项目直接拼接会导致架构混乱。
```

控制：

```bash
所有外部项目都通过 adapter 或 service 接入，不直接污染 Homepage 核心。
```

### 11.2 许可证风险

风险：

```bash
Homepage 和 Mineradio 都涉及 GPL-3.0。
```

控制：

```bash
项目整体按 GPL-3.0 开源。
保留许可证声明。
不直接使用 Mineradio 品牌名、Logo 和强识别视觉资产。
```

### 11.3 计时器复杂度风险

风险：

```bash
弹性计时器容易越做越复杂。
```

控制：

```bash
第一版只做正向计时、任务关联、手动拆分、休息提醒、AFK 校准。
复杂自动规划后置。
```

### 11.4 ActivityWatch 依赖风险

风险：

```bash
用户没有安装或启动 ActivityWatch。
```

控制：

```bash
ActivityWatch 是增强模块，不是硬依赖。
未连接时显示提示，但不影响任务和计时器使用。
```

### 11.5 音乐平台风险

风险：

```bash
音乐平台接口、登录态和版权规则复杂。
```

控制：

```bash
音乐模块只做用户自有账号和本地体验辅助。
不提供破解、绕过会员或重新分发能力。
第一版音乐模块保持轻量。
```

## 13. 总结

本项目应以 Homepage 为主界面 base，但产品核心不是“另一个 Homepage 主题”，而是“全流程工作站”。

Homepage 负责：

```bash
看见、布局、配置、展示。
```

Workbench-core 负责：

```bash
状态、规则、任务、计时、复盘。
```

ActivityWatch 负责：

```bash
真实电脑行为证据。
```

Mineradio 负责：

```bash
音乐体验和情境播放。
```

Super Productivity 负责：

```bash
任务模型参考。
```

BreakTimer 负责：

```bash
休息提醒机制参考。
```

原 Task-Manager 负责：

```bash
时间分配语义、token/GitHub 统计和复盘雏形。
```

最终目标是形成一个能支持学习、开发、写作、音乐、休息和复盘的本地优先工作站，并提供 Docker 和 Windows 两种分发方式。
